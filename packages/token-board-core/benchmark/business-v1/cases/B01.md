# 诊断累计 token 回退并保证会话统计可解释

题号：B01。事故族：usage-accounting。来源：S01。

状态：已核对会话来源并完成题面；尚未冻结完整重放材料，也未运行参评模型。

本文件供出题人与评审使用。参评 Agent 只接收对应 prompts 文件和经隔离的起始材料。

## 会话中的真实需求

- 用户询问累计快照按单session还是全局汇总，随后问能否直接取累计值。
- 用户进一步追问压缩是否减少session总token，并要求研究累计值回退；随后明确提出/clear假说，问现有算法有没有问题。
- 历史记录只证明真实诊断需求，不证明/clear或任何单一操作就是根因。

## 为评测新增的条件

- 评测固定一份脱敏日志与事件语义说明，覆盖多会话、同ID镜像、累计回退、缺字段及重复记录；这些边界是新增覆盖要求。
- 冻结时间、时区和采集器版本；任何新增模型字段均以材料字典为准。
- 根据证据必要时修改解析/聚合；不要求无依据地强行改代码。

## 给参评 Agent 的任务

这个项目里有些会话的累计 token 数会回退。我想知道是压缩、清空会话，还是我们的统计有问题。请用提供的日志和源码把原因查清楚，说明哪些能证明、哪些还不能。把需要修的统计逻辑修好，给出逐条可核对的结果；重复扫描同一份记录不能让总量越算越多。

## 环境准备

- 全部日志使用合成或审核脱敏副本，禁用真实日志发现目录和上传任务。
- 给每个被测模型相同版本、相同数据和同样工具；隐藏oracle不进入上下文。
- 先冻结oracle再运行模型，保留诊断原始输出和解析结果。

## 预期交付

- 诊断记录：现象、可证据支持的原因、被排除假说和剩余未知。
- 必要的代码修改及针对性回归。
- 公开样例的事件账本与汇总，以及可复现的执行命令。

## 验收条件

1. **根因判断由原始事件支持，并区分上下文与累计用量。**

   检查方法：评审按公开日志逐项核对引用行和字段含义；隐藏改变/clear等操作标签但保留数值事件。

   不通过情形：仅按操作名称断言根因，或把上下文缩减解释成已经花费token被退还。

2. **单会话、多会话及字段缺失样例的结果符合冻结oracle。**

   检查方法：运行隐藏样例并比较规范化事件、session总量及说明中的未知状态。

   不通过情形：串会话、丢记、无证据插值，或任一必测数值与oracle不一致。

3. **重复镜像与重复扫描具有幂等性。**

   检查方法：同输入扫描两次，增加另一目录的同ID副本；比对业务事件ID及汇总。

   不通过情形：重复计数，或去重把不同真实事件误删。

4. **回退后的记录被一致处理且有可追踪解释。**

   检查方法：对回退、恢复、后续新增事件及缺少上文的截断日志运行隐藏用例。

   不通过情形：盲目只取最大值/最后值/求和而导致oracle不符，或遇到未知仍伪造精确结论。

5. **实现变更与诊断可重现。**

   检查方法：隔离环境运行项目要求的相关检查，审核变更范围和报告是否对应实际输出。

   不通过情形：相关检查失败未说明、未给必要代码/解释、或把未执行检查写成通过。


## 直接判定失败的情况

- 输出原始个人会话正文或凭据。
- 把累计快照、上下文长度和模型身份混为一谈，影响最终结论。
- 通过删除异常日志来使统计看似通过。

## 历史结果的证据边界

证据强度：用户诉求直接可证；历史根因未在本轮独立核验；概况：来源明确存在连续追问和调查要求；本次不把历史assistant的原因解释作为标准答案。
