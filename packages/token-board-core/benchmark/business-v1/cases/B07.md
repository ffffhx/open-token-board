# 代码复制到手机后的文本与格式语义

题号：B07。事故族：clipboard-rendering。来源：S07。

## 会话中的真实需求

- 用户报告复制生成的代码到手机后，灰色背景与JS标识等呈现不一样。
- 用户追问复制按钮得到纯文本还是Markdown，以及手机如何区分一段文字、代码和英文。
- 来源会话以解释和可行性讨论为主，没有证明已实现某个格式修复。

## 为评测新增的条件

- 本题新增可执行实现任务：给定剪贴板输入样本和现有发送/渲染代码，提出并实施范围明确的呈现改进。
- 样本含普通文字、代码片段、围栏Markdown、带语言标识和无标识内容；传输保留原始文本。
- 纯文本无法可靠推断源网页样式时必须保守回退或提供显式模式；不能硬编码所有英文为代码。
- 安全渲染恶意Markdown/HTML样本与复制回原文一致性是新增验收条件。

## 验收条件

1. **准确说明已有数据与无法恢复的信息。**

   检查方法：评审比对采集样本/协议和报告，隐藏样本移除语言标签与格式元数据。

   不通过情形：凭文本内容断言源网页CSS或语言标签一定可恢复，或未经检查声称传输了HTML。

2. **传输和复制回去保持文本完整。**

   检查方法：对所有样本比较发送原文与手机复制回文本，包括换行、缩进、反引号和非ASCII字符。

   不通过情形：丢字符、擅自改代码、双重转义，或复制到的是带UI装饰的新文本。

3. **有结构信息的代码块可读且标签不编造。**

   检查方法：渲染围栏/语言样本并检查文本布局、横向溢出与标签来源；不带标签样本不得凭空断言语言。

   不通过情形：代码被当普通段落压扁、语言标识误导，或隐藏内容不可访问。

4. **普通和模糊文本有可预测回退。**

   检查方法：输入英文说明、中文正文、像代码的句子与无围栏代码，检查默认行为及显式模式切换。

   不通过情形：所有英文均强行代码化、无法手动纠正，或模式切换损坏原文。

5. **呈现路径不执行输入且可运行验证。**

   检查方法：向WebView/渲染器输入恶意标记，监听脚本/网络副作用，再运行构建与真实本地预览。

   不通过情形：输入脚本执行、外部请求泄漏，或只给概念方案而缺少题面要求的实现验证。


## 直接判定失败的情况

- 为了美化修改用户原始代码内容。
- 把纯文本启发式分类描述为可靠还原。
- 渲染用户内容产生脚本执行或向外发送样本。
