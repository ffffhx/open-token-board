# 修复报告

已修复题面中可以稳定复现的两个问题。只修改了 `src/render-root.mjs`、`src/profile-catalog.mjs` 和本报告；没有修改 adapter、demo 或任务说明。

## 原因与修改

名称输入位于整页 `innerHTML` 内，busy 或状态变化导致重绘时，原输入框被销毁，新输入框再次读取已保存名称。因此未提交的草稿会被覆盖。现在重绘前读取当前改名表单的实时值，重绘后通过输入框的 `value` 属性恢复，只对同一 modal 对象及同一 Profile 生效。关闭、重新打开、切换 Profile，以及进入 mini/loading 时会结束该编辑会话。直接设置 `value` 不把草稿拼接进 HTML，空字符串和 HTML 特殊字符也能保留。内容未变且编辑会话未变时仍沿用原来的 HTML 比较，避免重复重绘。

候选目录此前直接从运行快照取值，快照不存在或超过 30 秒就返回空数组。现在首先从注册表建立已配置 Profile 列表，缺失/过期快照仅表示 `running=false`。新鲜快照只有在 Profile ID 和端口都匹配时才补充运行信息；名称和 Agent 连接限制始终以注册表为准。快照中的未注册条目不会变成候选。

注册表沿用现有路径候选逻辑，支持 Windows、macOS、Linux、新旧应用目录、`env.CPM_DATA_DIR`，以及 `APPDATA` / `XDG_CONFIG_HOME`。按优先级读取首个结构有效的注册表；不存在、读取失败或 JSON/结构错误时尝试后续路径，全部失败返回空列表。有效的空注册表保持权威，不继续读后备数据。规范化时过滤缺字段、非法端口、重复 ID/端口，以及绝对路径、盘符路径、空目录、空字节和词法越界目录。

无论快照是否存在，都通过原有租约与进程存活逻辑核对占用。保留其他 session 排除、同 session 复用、禁止 Agent 连接、`excludedPort` 和端口排序行为；未改写租约有效性规则。

## 未覆盖的边界

这是提取代码与固定 adapter 的验证。模拟重启是使用内存后端数据重新配置 UI，不是真实桌面应用重启，也没有验证真实磁盘持久化。未运行完整 Electron/IPC、真实浏览器启动、真实 Profile/凭据访问或浏览器端 E2E。最小 DOM 不模拟焦点、光标、布局或输入法；路径检查验证的是词法边界，不涉及真实磁盘符号链接。历史截图中“保存成功后弹窗仍在”没有被稳定复现，本次不宣称找到了它的唯一根因；仅确认固定保存流程成功后 modal 清空、表单移除。
