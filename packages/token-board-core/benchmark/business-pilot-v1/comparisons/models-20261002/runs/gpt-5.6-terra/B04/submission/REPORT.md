# B04 修复报告

## 原因与改动

重命名弹窗是非受控输入，但根渲染器会在 busy/status 状态变化时整体替换 HTML；替换前没有读取输入值，因此草稿被已保存名称覆盖。渲染器现在只在同一个重命名弹窗仍打开时捕获并恢复输入值。草稿按 Profile ID 绑定，切换 Profile 或关闭弹窗会清除它；成功保存仍由现有提交流程更新状态并关闭弹窗，失败后草稿可继续提交。

目录册此前把运行快照当成唯一数据源，快照缺失或超过 30 秒便返回空结果。目录册现在读取受支持位置（含 `CPM_DATA_DIR`）的 `profiles.json`，校验必填字段、端口和 `profiles/` 目录边界，并以登记数据生成候选。新鲜快照仅补充同一公开 Profile ID 的运行状态；登记名称、端口和 Agent 连接限制保持优先。租约检查、同 session 复用、排除端口及排序保持生效。

## 已运行验证

- `node demo.mjs --once`：busy 重绘后草稿仍为 `After user input`；没有运行快照时，登记的 `isolated:demo` 仍作为 `running: false` 候选返回。
- 通过标准输入执行的 Node 夹具检查：验证固定端口优先、回退端口、非法/越界登记项过滤、无快照条目、运行快照合并、其他 session 占用、同 session 复用和禁止 Agent 连接。
- 通过标准输入执行的 Node DOM 夹具检查：验证 HTML 特殊字符草稿、失败后重试、busy/status 重绘、成功关闭弹窗、切换/取消不泄漏草稿及模拟重启后的保存状态。
- 启动 `node demo.mjs`，隔离地址 `http://127.0.0.1:50930/` 返回 HTTP 200；服务随后已停止。
