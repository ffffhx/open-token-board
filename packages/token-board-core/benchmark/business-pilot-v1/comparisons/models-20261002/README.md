# 八模型真实工作题比较

已完成截图中 8 个型号 × 3 道真实工作题，共 24 份有效作答。每题使用独立新上下文、相同冻结输入与工具环境，实际会话日志均为 medium。此前两份默认 low 的运行完整保留并排除，另开新会话从初始副本重跑；没有把答案或验收反馈发给参评 Agent。

难度复核后，本轮仅作为基础流程检查，不再据此给出个人工作模型推荐。两道编程题的核心功能在统一复核后均为 8/8 通过：输入已提前定位故障文件或提供现成导出、同步函数，省去了真实工作的主要定位过程。GPT-6 Astra 在完整交付通过组中的本轮耗时最短，这一观察仍保留，但不足以支持此前的优先候选建议。历史材料更完整的重放题另立新版，不覆盖本轮提交与原始分数。

分数始终是冻结评分器的原始检查计数。“通过（复核）”表示评分器误判已按全体模型统一规则纠正，具体依据保存在相应记录中；不会把原分数改成满分。“完整交付”同时检查功能、改动范围、事实依据和要求提交的可读报告。

本轮真正出现的交付问题：

- GPT-6.1 Sol 的 B11 发布实现通过全部 19 项功能检查，但落盘 REPORT.md 中中文变成 831 个字面问号，根因和验证说明无法阅读，因此完整交付未通过。原文件保留，未替它修复。
- GPT-5.6 Terra、GPT-5.6 Luna 的 B09 都找对恢复版本，项目 2 的业务文字未改，但各删除了受保护区末尾一个换行。两者还把来源中“现有工具普遍无法解决”扩大为被评测的五款工具全部失败。分别属于字节保留不精确和评测结论扩大。
- GPT-5.5 的 B09 保留了正确版本和受保护字节，但新增“悬浮控制条显示任务状态”这一资料未证实的具体功能，因此事实复核未通过。不能据此断言真实产品一定没有该功能，只能判定提交超出指定资料。
- 三题分别测试状态重绘与配置目录、历史版本恢复与限域改写、静态构建和私有内容发布。代码题经统一复核后区分度较低；一次答对不能证明复杂场景同样可靠。

评分复核按[统一规则](adjudication.json)适用于每个模型，题目、参考答案和冻结评分器始终未改：

- B04 题面要求 env.CPM_DATA_DIR，但未声明函数 input.env 参数。四份使用正常 process.env 的提交在私有调用约定上被扣分。对全部八份提交运行[补充检查](check-b04-env.mjs)，通过 process.env 注入同一组端口回退、非法端口、目录越界和缺字段案例；未修改参评源码。原始起点失败，参考修复通过。
- B09 把来源中的章节号“3.3”误当业务指标，且要求题面未明确规定的新增 Markdown 引用格式。正确章节引用、未新增链接格式不作为失败；事实依据、已有链接有效性和受保护字节要求仍保留。
- GPT-6.1 Sol 的报告乱码是交付内容复核发现的真实问题，功能评分器只检查报告存在，因此仍保留 19/19。复核由协调 Agent 完成，不是人工评审。
- 八份 B09 正文另外用 A–H 匿名编号交给一个新上下文复核员，不提供型号和分数。[逐份来源复核](semantic-blind-review.json)保留结论和协调者裁决。合理转述不判错；GPT-5.6 Sol 对 Ticket 申领连接的措辞标为推论提示，不作为明确编造扣分。

耗时来自各子会话 task_started 至 task_complete，包含工具执行和等待，不含排队；并行任务耗时求和不是整场墙钟时间。Token 是日志累计 API 用量，可能重复包含系统提示和历史输入，不是上下文长度或真实账单。缓存比例、模型与工具等待均影响比较；未采集真实费用，成本为 null。推理输出是输出 token 的子集，不另加到总数。

给参评模型的是与历史依据对应的独立材料副本，未让它们根据当前项目猜测。B04 使用历史函数与固定 adapter；B09 使用脱敏 Read/Edit 文档快照；B11 是基于历史源码的缩小重建。各题历史 commit、转换方式和未覆盖范围见[题包说明](../../README.md)。三题不是完整生产环境复现，尤其不包括真实 Electron、远程部署或原生 Ctrl+S 日志。

每个模型每题只保留一次有效 medium 作答，共 24 个单轮上下文；样本太少，未计算可靠胜率或置信排名。输入导出与上下文独立不等于操作系统沙箱，宿主工具拥有文件系统权限。会话 turn_context 核对的是调用配置，不能独立证明供应商内部后端身份。截图中的八个原型号均实际调用，未用替代型号；CLI 仅用于读取帮助，没有混入其他客户端或 API 的模型结果。
