## 复跑方法

在仓库根目录运行以下命令。输出目录必须不存在，替换示例中的盘符和目录即可；三题均可使用同样流程。

```powershell
node tools/eval-runner/business-pilot.mjs check
node tools/eval-runner/business-pilot.mjs validate
node tools/eval-runner/business-pilot.mjs prepare B04 --out C:/eval-runs/B04-trial-2
```

把导出的目录交给一个新 Agent 会话，让它阅读 `TASK.txt` 并完成任务。题包旁边的 `.receipt.json` 留给评审，记录初始文件哈希。Agent 结束后从题包外评分：

```powershell
node tools/eval-runner/business-pilot.mjs grade B04 --workspace C:/eval-runs/B04-trial-2
```

`validate` 只检查题目、参考修复和对照，不调用模型；`prepare` 只导出文件；`grade` 检查改动范围并运行独立验收器。本次模型调用由协调会话派发独立 Agent 完成，尚未接入现有排行榜或一键多供应商调度。

`grade` 中的 `manualReview: pending` 表示仍需要内容复核。此次协调 Agent 对提交及报告作了语义复核，结果与机器评分分别记录；没有冒充人类评审。切勿以报告文件存在或关键词命中证明报告的每项测试声明。

已有结果对应当前冻结哈希。修改题目或 runner 后应生成新版本并重新校验、导出和试跑；`freeze` 会重写清单，不应对旧结果静默替换版本。

## 运行记录与边界

[pilot-results.json](pilot-results.json) 保存机器结果、复核结论与限制；`runs/pilot-1/` 保存各题提交的改动文件、评审摘要和哈希，便于复查。历史会话定位、完整本地路径和原始评分输出仅保存在被 Git 忽略的 `tests/.tmp/business-pilot-20261002/`。

各题 `task.json` 中若有 `validation` 字段，它是出题阶段的参考修复自检快照；实际参评次数与结果以 `pilot-results.json` 和运行记录为准。

本次为新会话与输入导出的上下文隔离。Agent 没有被提供答案或评分器，但宿主工具仍具备文件系统权限，未提供操作系统沙箱或防作弊保障。正式比较应使用独立容器或等效隔离，并固定模型标识、工具权限、预算和输入。

模型身份采用会话继承设置，未独立核实供应商实际后端；成本、生成 token 与准确作答耗时未采集，保持 `null`。评分器耗时只表示验收耗时。每题一次成功或失败都不足以推导稳定成功率，后续比较应换用明确的候选模型配置并保留所有重复试验结果。
