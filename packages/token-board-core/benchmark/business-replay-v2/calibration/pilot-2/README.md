# 历史业务题：三款模型补充试验

本轮按用户选择执行 GPT-6.1 Sol、GPT-6 Sol、GPT-6 Luna 各三题，共九个独立会话，7/9 次完整通过。每个模型每题只跑一次，不能由一次结果推出稳定排名或成功率。

沿用同一冻结题包和验收器。这一轮向所有参评者的初始消息直接提供完整题面，并统一提示 UTF-8 读取，减少 Windows 编码造成的干扰。这个输入呈现方式与 [首轮两模型校验](../pilot-1/README.md) 有差异，旧成绩不能冒充完全相同条件的重复试验。

全部会话使用 medium、全新上下文；依赖预装不计入作答时间，隐藏验收在提交后单独执行。表内 Token 是会话累计 API 用量，含重复与缓存输入，不是单次上下文大小；没有可靠账单数据，因此不填费用。时间包括模型自行阅读、修改和自测，不含提交后的独立评分。

每次试验允许模型在 45 分钟内自行修改和自测；“一次”指该独立会话的首次正式提交。提交后不回传隐藏得分、不补改答案、不挑选重跑中的最好成绩。

## 未完整通过的原因

- **gpt-6-sol / B09**：开场文字版本选择正确，项目事实复核也通过；但漏掉历史E0243第22行的Markdown分隔线，按冻结的结构保留规则未完整通过。不能把此结果解释为找错历史文字版本。自测真实执行但只比较标题起的片段，遗漏前置分隔线，不作为伪造验证另扣交付；末尾空行差异仅记格式。
- **gpt-6-luna / B09**：项目1的事实与角色关系基本有据，但开场未恢复。报告漏掉E0243/E0258/E0288的重复读取及E0301编辑前原文，错误认定材料不足；没有原生Ctrl+S事件不妨碍用这些证据选择恢复区域。因此业务与证据链交付未通过，不指控伪造测试。单独启动浏览器的表述存在解释空间，按有限设计概括处理，不另作失败依据；末尾空行只记格式。

## 评分边界

B02、B04、B09 的历史基线均复现预期问题，参考修复均通过；12 个错误或不完整修复对照均触发预期失败，4 个合理替代对照通过。其中一项虚构成果对照由来源复核否决，不能算作自动检查已识别全部事实错误。这些证据支持当前验收器能识别已覆盖的问题，不代表已经穷尽所有正确解法或缺陷。

B02 使用真实隔离 PostgreSQL 和完整历史 API/Core，检查 54 种统计组合、刷新性能、读取可用性与故障恢复。B04 使用真实 Chromium DOM、ProfileManager 落盘及临时租约文件，检查改名和目录一致性。B09 使用完整历史文档与原始操作时间线；事实判定按来源逐项复核，并与候选文件 SHA 绑定。复核者为协调 Agent，不冒充人工评审。

业务、交付和格式单独记录。B09 的数字扫描只提醒复核，不能仅凭出现数字判失败；末尾空行等格式差异也不单独否决业务。所有首次提交和原始机器结果保留，没有根据分数补改模型代码或重跑挑选最好成绩。

本轮 GPT-6 Sol 的 B09 找回了正确文字，仅遗漏开场前的 Markdown 分隔线；冻结规则把内部 Markdown 结构纳入恢复验收，因此该项仍记失败。这与 GPT-6 Luna 漏看历史证据、没有恢复开场的失败程度不同，不能只看通过数量就断言两者能力相同或明显落后。若希望格式与实质内容完全分开，需在下一版本预先调整评分规则并统一重测，不能在看到模型身份和结果后改本轮成绩。
