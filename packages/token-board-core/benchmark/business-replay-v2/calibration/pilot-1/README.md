# 历史业务题小样本校验结果

本轮按预先约定执行两个模型各三题，共六个独立会话，3/6 次完整通过。它用于检查新版题目难度和评分是否合理，不能由一次结果推出模型排名或稳定成功率。

历史材料导出、独立作答、自动验收、来源复核和提交归档的流程已跑通。本次观察到了读取延迟超标、跨模块修复遗漏和无来源事实断言，说明新版能暴露与实际交付有关的问题。题面编码和性能波动仍影响结果；正式扩大比较前，应在新协议中统一文本读取环境并预先安排重复试验，保留本轮首次记录。

## 未完整通过的原因

- **gpt-5.6-luna / B02**：独立验收54组合、历史修正、并发刷新、失败保全、恢复、重启和空数据均通过，刷新中位数8899.4→6314.8ms、7/7配对改善；但读取P95为126.3ms，超过按基线计算的104.7ms门槛。交付报告与实际自测日志一致、服务可访问，因此交付通过；自测为前后顺序七轮，不能替代外部交替配对验收。
- **gpt-5.6-luna / B04**：首次提交只修改 ProfileManager，后台加载吞草稿和离线目录缺失均未解决，10 项业务检查全部失败。普通 smoke 通过及其他检查未跑通的记录真实，但最终声称完成修复并保证目录一致，超出了验证证据。初次 TASK.txt 被 PowerShell 默认编码读成乱码，未见正确重读；此结果包含工具使用因素，不能只归因于业务推理能力。
- **gpt-5.6-luna / B09**：正确恢复保存版本且正文结构可读；末尾少一个空行只记格式。新增Playwright/Puppeteer无法覆盖三类能力的无条件断言超出资料，报告又声称全部事实已由资料核实，因此事实与交付复核失败。Gateway仲裁的职责概括有解释空间，不作为独立失败依据。

## 性能题独立测量

- gpt-6-astra：独立验收基线中位数 7900 ms，提交中位数 1642 ms；7/7 轮配对改善。性能项通过，业务结论仍需同时满足完整统计、读取与故障恢复。 刷新期间读取 P95 为 95.8 ms，门槛 100.0 ms，通过。 读取延迟接近门槛，一次通过不能证明稳定达标。
- gpt-5.6-luna：独立验收基线中位数 8899 ms，提交中位数 6315 ms；7/7 轮配对改善。性能项通过，业务结论仍需同时满足完整统计、读取与故障恢复。 刷新期间读取 P95 为 126.3 ms，门槛 104.7 ms，失败。

## 解释结果时的限制

- gpt-5.6-luna / B04：中文 UTF-8 题面被 PowerShell 默认编码读成乱码，未见正确重读。可读材料本身可用，但这次结果混有工具使用因素，不能只归因于业务推理能力。

后续若要单独比较业务推理能力，应在新协议中统一把题面直接放进提示，并固定 UTF-8 读取方式，再开新会话。当前记录保持首次真实轨迹，不事后修补输入或挑选重跑结果。

## 评分边界

B02、B04、B09 的历史基线均复现预期问题，参考修复均通过；12 个错误或不完整修复对照均触发预期失败，4 个合理替代对照通过。其中一项虚构成果对照由来源复核否决，不能算作自动检查已识别全部事实错误。这些证据支持当前验收器能识别已覆盖的问题，不代表已经穷尽所有正确解法或缺陷。

B02 使用真实隔离 PostgreSQL 和完整历史 API/Core，检查 54 种统计组合、刷新性能、读取可用性与故障恢复。B04 使用真实 Chromium DOM、ProfileManager 落盘及临时租约文件，检查改名和目录一致性。B09 使用完整历史文档与原始操作时间线；事实判定按来源逐项复核，并与候选文件 SHA 绑定。复核者为协调 Agent，不冒充人工评审。

业务、交付和格式单独记录。B09 的数字扫描只提醒复核，不能仅凭出现数字判失败；末尾空行等格式差异也不单独否决业务。所有首次提交和原始机器结果保留，没有根据分数补改模型代码或重跑挑选最好成绩。
