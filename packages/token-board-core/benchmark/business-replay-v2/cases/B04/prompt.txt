ProfilePilot 的 Profile 管理最近出现两类用户可见的不一致，需要在这份历史项目中排查并修复。

用户反馈：“名称需要修改两遍才会生效。”在主窗口刚出现、后台设置仍在加载时打开独立 Profile 的改名窗口，输入新名称再保存，可能仍看到旧名称。这份版本还可复现另一项业务不一致：关闭管理窗口一段时间后，Agent 工具看不到已经登记的可启动 Profile；管理界面和 Agent 候选列表也可能显示不同名称。

请修复实际业务链路，满足以下验收：
- 用户在改名窗口输入的内容应能在首次有效提交时保存，并在重新读取登记信息后保持一致。后台状态变化不能吞掉未提交内容。取消后重新打开或改名另一个 Profile，不得带入前一个未保存草稿。空名称仍按既有校验处理。
- 已登记、端口有效的独立 Profile 应能被 Agent 工具发现，即使管理窗口未运行，或其运行状态信息已经过时/暂时无法读取。登记名称和 Agent 访问设置需要及时生效；运行状态必须有有效的对应依据，不能把端口上另一个 Profile 的状态归给当前 Profile。原本可发现的新鲜运行项也应保留，即使它不属于这批独立 Profile 登记；过时的临时运行项不再代表可用目标。
- 仍须遵守已有租约和 Agent 访问开关：其他 Session 占用的 Profile 不可推荐给请求者，同一 Session 的占用可继续使用；排除当前端口，候选按端口顺序返回。已有租约不能仅因为管理窗口关闭而失效。
- 保留既有名称校验、其他 Profile 的登记信息、合法自定义数据目录，以及对无效登记项/越界路径的处理。不要引入网络依赖或要求用户重开浏览器、重复保存。
