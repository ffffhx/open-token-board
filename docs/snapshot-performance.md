# 榜单快照性能验证（2026-09-14）

## 线上基线

- 主机：2 核、约 3.5 GiB 内存，与其他应用共享。
- PostgreSQL：约 496,481 条用量事件，事件表及索引约 289 MB。
- 优化前刷新 54 份快照约需 16 分钟；配置的 60 秒只是触发间隔。
- API 容器采样约占一个 CPU 核心、1.4 GiB 内存。
- 简单 SQL 分组求和单次执行：当天约 0.6 ms，90 天约 460 ms；这些数字不代表完整榜单耗时。

## 本次改动

PostgreSQL 快照按时间范围计算公共统计，再生成六种指标的排序及上期排名变化。
同一轮内仅对相同用户集合复用荣誉结果，避免改变依赖团队中位数的徽章口径；缓存不跨刷新轮次保存。

快照刷新在独立子进程执行，数据库连接默认只读、单连接，并有查询及整个任务的超时。
HTTP 进程继续提供上一份完整快照；任务失败不会用不完整结果覆盖缓存。
原有 JSON 文件存储路径保持兼容。

健康接口新增 `refreshStartedAt`、`lastCompletedAt`、`lastDurationMs`、`ageMs` 和 `stale`。
`lastRefreshAt`/快照 `generatedAt` 仍表示本轮统计的参考时间，`lastCompletedAt` 表示真正完成时间。
快照年龄超过两个配置刷新间隔时 `stale` 为 true，不能只用 HTTP 200 判断数据新鲜度。

## 正确性验证

- 原有 55 项 API 测试通过；Core/API TypeScript 检查通过。
- 在隔离 PostgreSQL 容器中，直接使用部署前的存储模块作为对照，全部 9 个范围 × 6 个指标的结果完全一致。
- 覆盖并列排序、缺失行数、不同时间范围的用户集合、历史数据修正、子进程 JSON 传输、超时、SQL 失败及失败后恢复。
- 本地没有 PostgreSQL 时，新测试会明确跳过。可针对专用测试数据库运行：

```powershell
$env:TOKEN_BOARD_TEST_DATABASE_URL = "postgresql://user:password@localhost/test_database"
corepack pnpm exec tsx --test tests/api/leaderboard-batch.test.ts
```

该测试只创建随机命名的测试 schema，并在结束后删除；不要把测试连接指向生产数据库。
可设置 `TOKEN_BOARD_BASELINE_STORAGE` 为旧版存储模块的绝对路径，对比旧版实现。

## 线上只读对比方法

独立容器限制为 0.75 CPU、1,200 MiB 内存，Node 堆限制 768 MiB；旧线上服务继续运行。
固定统计参考时间为 `2026-09-14T14:55:00Z`，旧版先计算当天六种排序，新版计算全部 54 份快照，逐项检查当天结果。
这不是吞吐量压测；部署后的正常刷新日志及接口小样本用于确认实际改善。

## 结果

| 测量 | 结果 |
| --- | --- |
| 限额容器：旧版当天六种排序 | 187,067 ms |
| 限额容器：新版全部 54 份快照 | 162,290 ms |
| 上述对比中的当天六种结果 | 全部一致 |
| 新版线上首轮完整刷新 | 68,261 ms |
| 刷新期间 20 次本机请求（今天/7D 交替） | 中位数 15.65 ms，P95 24.1 ms，最大 47.78 ms |
| 刷新结束后的 API 容器内存采样 | 145.7 MiB |

线上首轮于 UTC 15:09:41 开始、15:10:49 完成，相比之前日志中的约 16 分钟缩短约 93%（约 14 倍速度）。
这里的线上前后比较不是相同负载下的严格基准：数据期间仍有正常上传，限额测试时旧服务也在运行。
接口数据已经更新，文件内 54 份快照与 API 中的当天结果一致；公网健康接口也已确认新版字段与完成时间。

刷新期间计算子进程仍会占用较多 CPU 和内存；完成后退出并释放内存。145.7 MiB 是刷新间歇的采样值，不能当成峰值。
目前完整刷新仍略超 60 秒，定时触发会合并到正在运行的任务，不能宣称数据每分钟必定更新。
自定义日期、个人详情等其他实时计算路径未在本次迁移到子进程。

## 部署与回滚

仅更新 API 的 `server.ts`、快照 job/worker 和 Core 的存储模块；没有修改数据库 schema 或部署环境变量。
使用原部署镜像为基础生成新镜像，避免把无关本地改动或依赖变动带到线上。

- 部署镜像：`token-board-service:snapshot-20260914`
- 原镜像保留为：`token-board-service:before-snapshot-20260914`
- 服务器对比脚本、原始源码和测量摘要：`/home/deploy/token-board-perf-20260914/`
- 隔离测试数据库及网络、只读基准容器已清理。

需要回滚时，在服务器部署目录将原镜像重新标记为 `token-board-service:latest`，再运行 `docker compose up -d --no-deps token-board`。
如果还要恢复下一次构建使用的源码，可使用上述目录 `src/server.baseline.ts` 与 `src/token-board-storage.baseline.ts` 的备份。
